- 가시성: Public
- 기본 브랜치: `main`
- 기준 커밋: `430114922d455804bb7d8b2ecb3872e21670b680`
- 감사 기준일: 2026-08-04

## 2. 현재 구현 개요

현재 애플리케이션은 다음 세 파일과 이미지 폴더로 구성된 단일 페이지 정적 갤러리입니다.

- `index.html`
- `script.js`
- `style.css`
- `assets/images/*.png`

`script.js`의 `allImages` 배열에 파일명을 직접 등록하고, 파일명 접두어를 카테고리로 사용합니다. 브라우저에서 모든 이미지를 슬라이드 DOM으로 생성한 뒤 현재·이전·다음 위치를 CSS class로 전환합니다.

## 4. 현재 데이터 구조

현재 이미지 정보는 파일명 문자열 하나로 표현됩니다.

```text
community_community-discovery.png
old_old_home-landing.png
slide_Gemini_Generated_Image_tlt4p0tlt4p0tlt4.png
```

파일명에서 첫 번째 `_` 앞부분을 category로, 두 번째 조각을 title로 사용합니다. 따라서 다음 정보는 구조화되어 있지 않습니다.

- 고유 ID
- 사용자용 제목
- 상세 설명
- 플랫폼
- 상태
- 제품 버전
- 생성·캡처일
- 출처 저장소·커밋
- 공개 승인 상태
- AI 생성 여부
- 현재·과거·컨셉 구분
- 정렬 순서
- featured 여부
- 대체 자산 관계

## 5. 주요 기술 문제

### 5.1 모든 이미지 동시 생성·로딩

`renderSlider()`는 필터에 포함된 모든 이미지에 대해 `<img>`를 생성합니다. 전체 보기에서는 34개 PNG가 동시에 DOM에 들어갑니다.

영향:

- 초기 네트워크 사용량 증가
- 모바일 데이터·메모리 부담
- 대형 PNG 디코딩 비용
- 이미지 증가에 따른 성능 저하

### 5.2 파일명 기반 제목 손실

`img.split('_')[1]`만 제목으로 사용하므로 `_`가 여러 개 있는 파일은 제목 정보가 잘립니다.

예:

- `old_old_home-landing.png` → `old`
- `introduce_Gemini_Generated_Image_...png` → `Gemini`

### 5.3 카테고리 불일치

파일명 접두어에는 다음 영역이 존재합니다.

- community
- editor
- empty
- home
- introduce
- login
- memory
- mobile
- my-trees
- old
- search
- settings
- slide

하지만 UI 필터는 일부만 제공합니다. Empty, Introduce, Login, Memory, My Trees, Search, Settings를 개별 필터로 탐색할 수 없습니다.

### 5.4 자산 상태 불명확

실제 제품 캡처, AI 생성 소개 이미지, 발표 슬라이드, `safe`, `bts`, 이전 화면이 한 목록에 섞여 있습니다. 사용자는 해당 이미지가 현재 제품의 실제 화면인지 판단하기 어렵습니다.

### 5.5 원본과 배포본 미분리

모든 이미지는 PNG 원본 형태로 `assets/images/`에 있습니다. 웹 최적화본과 썸네일이 따로 존재하지 않습니다.

### 5.6 확장 불가능한 인디케이터

이미지마다 점 하나를 만들기 때문에 34개에서도 모바일 폭을 초과할 수 있습니다. 이미지가 더 증가하면 탐색 수단으로 사용할 수 없습니다.

### 5.7 모바일 레이아웃 제약

- `body`에 `overflow: hidden`
- `height: 100vh`
- 필터 줄바꿈·가로 스크롤 없음
- 이미지·제목·인디케이터가 고정된 세로 공간을 경쟁
- 별도 모바일 media query 없음

### 5.8 접근성 부족

- 이전·다음 버튼에 접근 가능한 이름 없음
- 인디케이터가 `div`여서 키보드 선택 불가
- 필터 선택 상태를 `aria-pressed` 등으로 전달하지 않음
- 현재 슬라이드 변경 안내 없음
- 의미 있는 이미지 대체텍스트 부족
- `prefers-reduced-motion` 미지원
- `focus-visible` 기준 없음

### 5.9 오류 처리 없음

- 이미지 404 처리 없음
- 빈 필터 상태 없음
- 매니페스트와 파일 불일치 검사 없음
- 이미지 크기·해상도 검사 없음

### 5.10 개발·배포 프로세스 없음

- README 부재 상태에서 시작
- 이슈·PR 템플릿 없음
- 테스트 없음
- CI 없음
- 배포 workflow 확인되지 않음
- 자산 추가·삭제·보관 기준 없음

## 6. 공개 저장소 관련 운영 문제

저장소가 Public이므로 다음 사항이 자산 단위로 검토되어야 합니다.

- 실제 사용자 개인정보가 포함되었는가
- 미출시 화면 공개가 승인되었는가
- 제3자 이미지·브랜드·폰트 사용 권한이 있는가
- AI 생성 이미지를 실제 화면처럼 오인하게 하지 않는가
- 공개 중단이 필요한 자산을 즉시 찾을 수 있는가

이는 저장소 전체를 비공개로 전환해야 한다는 의미가 아닙니다. 공개 상태를 유지하려면 자산별 공개 승인과 출처를 관리해야 한다는 의미입니다.

## 7. 현재 강점

- 설치 없이 실행 가능한 단순 정적 구조
- 34개의 LoveBud 시각 자료가 이미 한곳에 모여 있음
- 키보드·버튼·터치 이동 제공
- 과거 화면을 포함해 제품 변화 확인 가능
- 발표용으로 적합한 중앙 집중형 슬라이드 디자인
- GitHub Pages·Cloudflare Pages 등 정적 배포에 적합
