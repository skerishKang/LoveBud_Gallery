# LoveBud Gallery

LoveBud 제품의 홈, 러브트리 편집기, 커뮤니티, 추억, 검색, 설정, 모바일 화면과 과거 디자인·발표용 이미지를 한곳에서 탐색하기 위한 **공개 정적 제품 갤러리**입니다.

현재 구현은 HTML, CSS, Vanilla JavaScript로 구성된 단일 페이지 슬라이드쇼이며, 34개의 PNG 이미지를 카테고리별로 필터링해 보여줍니다.

## 프로젝트 상태

- 저장소: Public
- 기본 브랜치: `main`
- 기준 커밋: `430114922d455804bb7d8b2ecb3872e21670b680`
- 문서화 기준일: 2026-08-04
- 현재 단계: `STATIC_GALLERY_DEMO_COMPLETE / PRODUCT_ASSET_GOVERNANCE_DOCUMENTED`
- 프런트엔드: HTML, CSS, Vanilla JavaScript
- 백엔드·DB·인증: 없음
- 현재 이미지: PNG 34개
- 현재 데이터 원천: `script.js`의 하드코딩 배열
- 빌드·테스트·CI: 없음
- 배포 workflow: 저장소 파일 기준 확인되지 않음

## 프로젝트 목적

이 저장소의 1차 목적은 LoveBud의 화면과 시각 자료를 다음 용도로 일관되게 관리하고 보여주는 것입니다.

1. 현재 제품 화면 확인
2. 기능 영역별 UI 탐색
3. 모바일·데스크톱 화면 비교
4. 이전 버전과 현재 버전 비교
5. 발표·소개용 이미지 열람
6. 제품 회고와 신규 참여자 온보딩
7. 승인된 시안과 컨셉·보관 자료의 구분

## 현재 구현 범위

- 전체 이미지 슬라이드쇼
- 이전·다음 버튼
- 좌우 방향키 이동
- 모바일 스와이프
- 카테고리 필터
- 현재 이미지 번호
- 슬라이드 인디케이터
- 파일명 기반 카테고리와 제목 생성
- 다크 테마와 전환 애니메이션

## 현재 이미지 영역

현재 파일명 기준으로 다음 영역의 화면이 포함되어 있습니다.

- Community
- Editor
- Empty State
- Home
- Introduce
- Login
- Memory
- Mobile
- My Trees
- Search
- Settings
- Archive
- Presentation Slides

현재 필터는 일부 영역만 제공하므로, 모든 이미지가 개별 카테고리로 탐색되지는 않습니다.

## 현재 핵심 한계

- 34개 이미지를 한 번에 DOM에 생성하고 로드함
- 원본 PNG와 웹 최적화본이 분리되지 않음
- 이미지 제목·설명·상태가 파일명에 의존함
- `_`가 여러 개인 파일의 제목이 잘릴 수 있음
- 실제 제품 화면·AI 생성 이미지·발표 슬라이드·과거 화면이 구조적으로 구분되지 않음
- 필터가 모든 이미지 카테고리를 포함하지 않음
- 특정 이미지를 직접 여는 URL이 없음
- 그리드·썸네일 탐색이 없음
- 모바일 반응형 규칙과 세로 스크롤 정책이 부족함
- 이전·다음 버튼과 인디케이터의 접근성 정보가 부족함
- 이미지 로딩 실패·빈 카테고리 처리 없음
- 이미지 자산 검증·크기 예산·CI가 없음
- 공개 저장소에서의 자산 공개 승인·출처·라이선스 기록이 없음

## 공개 저장소 전제

이 저장소는 공개 상태입니다. 따라서 갤러리에 포함되는 자산은 다음 기준을 충족해야 합니다.

- 실제 개인정보나 비공개 사용자 데이터가 없음
- 미출시 기능의 공개가 승인됨
- 제3자 이미지·폰트·브랜드 사용 권한을 확인함
- AI 생성 이미지와 실제 제품 캡처를 구분함
- 공개 중단이 필요한 자산은 즉시 식별할 수 있음

공개 여부는 저장소가 Public이라는 사실만으로 자동 승인된 것으로 간주하지 않습니다. 각 자산의 상태는 매니페스트와 검토 기록으로 관리합니다.

## 개발 원칙

1. 파일명을 데이터 모델로 사용하지 않습니다.
2. 모든 자산은 고유 ID와 메타데이터를 가집니다.
3. 실제 제품·컨셉·발표·보관 상태를 명확히 구분합니다.
4. 원본과 웹 배포본·썸네일을 분리합니다.
5. 현재·이전·다음 이미지만 우선 로드합니다.
6. 모바일·키보드·스크린리더 사용성을 함께 검증합니다.
7. 공개 자산은 출처·승인·권리 상태를 기록합니다.
8. 모든 개발은 GitHub Issue와 PR 완료 조건을 기준으로 진행합니다.

## 권장 개발 순서

1. 이미지 매니페스트와 자산 상태 체계
2. 전체 이미지 인벤토리와 공개 승인 검토
3. 원본·웹·썸네일 구조와 이미지 최적화
4. 지연 로딩과 인접 이미지 선로딩
5. 그리드·상세 뷰어·deep link
6. 카테고리·플랫폼·상태 필터
7. 모바일·접근성 개선
8. 배포 구조와 CI
9. 필요 시 LoveBud 본 저장소와 캡처 자동 연계

문서화 단계에서는 기존 UI, 코드와 이미지 원본을 변경하지 않습니다.
